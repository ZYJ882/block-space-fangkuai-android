## 目标与结论

v1.22.1 已将局域网多人比赛固定为无垃圾行的纯竞速淘汰，以避免用户不喜欢的灰色垃圾行与断线误判。v1.23.0 将规则明确拆分为两个由房主在创建房间时锁定的模式：默认的 **竞速淘汰 / Race** 与可选的 **标准攻击 / Attack**。两种模式均采用 **FT3（先胜三局）** 多回合赛制；单局淘汰后会展示本局胜者和比分，再自动开始下一局。这既保持了默认 LAN 体验的稳定和简洁，也为希望使用现代攻防机制的玩家提供了清晰、可解释的可选入口。

| 模式 | 规则 | 灰色垃圾行 | 胜负与异常处理 |
|---|---|---|---|
| 竞速淘汰 / Race（默认） | 标准重力、固定 7-Bag、房主种子；不发送攻击 | 永不发送、接收或应用 | 真实堆顶才淘汰；FT3；来宾断线取消整场 |
| 标准攻击 / Attack（可选） | 标准重力、固定 7-Bag、房主种子；消行产生可抵消攻击 | 仅在未抵消攻击于 220ms 后到期时出现 | 真实堆顶才淘汰；FT3；来宾断线取消整场 |

## 标准攻击结算

攻击只在方块锁定后结算一次，避免移动、下落和状态同步频率导致的重复攻击。规则不通过中文得分标题反推，而是由游戏引擎显式输出的 `clearedLines`、`isTSpin`、`backToBackApplied`、`combo` 与 `perfectClear` 元数据计算。

| 事件 | 基础攻击行数 |
|---|---:|
| 单消 / 双消 / 三消 / 四消 | 0 / 1 / 2 / 4 |
| T-Spin 单 / 双 / 三消 | 2 / 4 / 6 |
| Back-to-Back | +1 |
| 连击 | 第 2 次连续消行起 +1，最多 +4 |
| All Clear | +6 |
| 单次外发上限 | 12 |

来袭攻击先进入按到期时间排序的本地队列。玩家在攻击到期前完成消行时，攻击会优先用于抵消待进入队列；只有未抵消余量被房主转发至自动选择的存活对手。这样可避免“消行后仍被同批攻击砸中”的不直观结果。规则循环同时等待游戏自身事件和最早垃圾到期事件，以保证 220ms 延迟不会被低重力或锁定等待拉长。

## 联机一致性与可靠性

所有多人房间强制 `SEVEN_BAG` 与标准重力。房主在开始比赛时生成一个 `Int` 种子，并通过 `START|模式|种子` 下发；所有设备以该种子重建 7-Bag 生成器。因此，连接正常的参赛者拥有相同的方块刷新序列，个人设置中的真随机或下落速度不会影响正在进行的比赛。

多人协议版本提升为 `4`。来宾在 `WELCOME` 消息中得知房间模式，开始消息再次携带模式和种子；非法模式、缺失种子、无效令牌、超长消息和超出单次上限的攻击均不会进入正常结算。旧协议客户端会在握手阶段被拒绝，而不是以不兼容规则参赛。

断线语义保持 v1.22.1 的可靠性修复：只有由本地游戏引擎产生的真实 `isGameOver` 才会发送淘汰；任一来宾的 TCP 断开或心跳超时都会广播 `ABORT` 并取消整场 FT3 比赛，绝不会将网络异常转化为另一名玩家的胜利。回合结果、下一局种子和最终结果均有单独消息；已进入最终结束状态的客户端会忽略迟到的回合结果，避免网络消息乱序将最终界面倒退为“即将下一局”。

## 建议真机局域网回归

应使用至少两台设备连接同一 Wi‑Fi 或热点，分别创建 Race 与 Attack 房间并逐项验证。Race 中连续四消不应产生灰色行；Attack 中双消、四消、T-Spin 与全消应按待进入提示产生可抵消的灰色行。两端的首块与三个预览应完全一致。每局结束后确认比分增加一次、全部玩家棋盘按新种子重置、累计三胜后才显示最终胜者。最后分别验证真实堆顶、来宾断网、房主退出和心跳超时：前者只结束对应回合，后三者均取消整场且不显示胜者。
