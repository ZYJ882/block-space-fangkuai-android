## 已修复问题

### 后台停留时间可能误推进游戏

事件驱动循环会在等待下一次规则事件时记录单调起点。若应用切入后台但协程继续运行，恢复或等待结束后，后台停留时间可能被当作重力或锁定的经过时间，使方块异常下落或直接锁定。

v1.15.1 通过 `LifecycleEventObserver` 监听 `ON_PAUSE` 与 `ON_RESUME`：进入后台时取消当前规则事件等待，恢复时以新的单调时间基准重新计算下一次到期事件。因此后台时间不会再进入重力、500ms 锁定延迟或出生直降保护的计时。

### 依赖管理与弃用 API

JUnit 已迁移至 `libs.versions.toml`；生命周期所有者改为 `lifecycle-runtime-compose` 提供的 `androidx.lifecycle.compose.LocalLifecycleOwner`，消除了旧 Compose 平台生命周期 API 的编译弃用提示。

## 后续真机建议

在真实 Android 设备上连续测试普通和极速档各 5 分钟，并重点验证：后台 30 秒后恢复、来电/通知遮挡恢复、锁定前 100ms 切后台恢复、以及连续长按移动。若需要量化帧时间，应在真机上使用 Macrobenchmark 与 Perfetto/Compose tracing 采集 `frameDurationCpuMs`、`frameOverrunMs` 和重组范围。
