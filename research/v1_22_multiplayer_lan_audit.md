# v1.22.0 局域网多人比赛审查记录

## 目标

将原有一对一局域网会话升级为同一 Wi‑Fi 或手机热点内的多人比赛房间。为了在手机屏幕可读性、主机负荷与局域网稳定性之间保持平衡，本版将单个房间限制为 **最多四名玩家（含房主）**。

## 房间与通信模型

| 项目 | 实现 |
|---|---|
| 房间发现 | Android NSD/mDNS 服务类型 `_blockspace._tcp.`；玩家可主动刷新搜索结果。 |
| 创建者角色 | 创建房间者是房主；负责在本地维护名单、接纳最多三名客户端、统一开始比赛和中继状态。 |
| 客户端连接边界 | 仅连接 NSD 已解析出的房主地址与端口；不做 IP 段扫描、互联网连接、云端转发、账户或文件传输。 |
| 协议边界 | UTF-8 单行消息，最大 1024 个字符；握手使用版本号、随机会话令牌和受限玩家标识。 |
| 房间容量 | 房主加最多三名来宾；满员或比赛开始后会拒绝新连接。 |
| 生命周期 | 退出、断线、取消、组件释放和比赛开始都会关闭相应 Socket，并停止发现、注销广播或释放组播锁。 |

## 比赛规则

房主在至少两名玩家进入大厅后点击“开始多人比赛”。所有已加入玩家在 `START` 广播后重置并开始同一轮游戏。每名玩家会实时同步已固定棋盘、分数、消行、当前方块和落点虚影；本机界面缩小主棋盘，并纵向呈现所有其他玩家的小棋盘。

双消、三消、四消分别向所有其他仍存活玩家发送 1、2、4 行带缺口垃圾。玩家游戏结束或连接断开后被标记为淘汰；当仅剩一名存活玩家时，房主广播最终胜者。多人比赛中的游戏结束覆盖层不会执行单人“再来一局”，而是显示淘汰或比赛结果并允许退出房间。

## 验证边界

| 验证项 | 结果 |
|---|---|
| Kotlin/Compose 编译 | 通过 |
| 既有游戏与垃圾行单元测试 | 30 项通过 |
| Debug APK 生成 | 通过 |
| APK 签名 | Android Debug v2 通过 |
| 真机多人发现与对战 | 需要至少两台、建议三至四台真实 Android 设备接入同一 Wi‑Fi 或热点完成最终验收。 |

当前构建环境无法同时运行多台 Android 真机，因此自动化验证覆盖代码编译、消息长度限制、游戏规则和 APK 完整性；应在实际局域网中验收房间发现、多人加入、房主开始、垃圾攻击、淘汰和断线场景。
