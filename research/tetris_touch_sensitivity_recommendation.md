# 方块空间：快速点击与长按灵敏度的科学建议

## 结论

不存在对所有设备、所有握持方式和所有玩家都“全球唯一最科学”的数值。更科学的做法是将 **点击响应**、**DAS** 与 **ARR** 分开设计，并以低误触率、可预测性和可调节性为目标。对于《方块空间》的移动端矩形按钮，建议保持“按下即触发”的单击逻辑，并以 **160ms DAS / 50ms ARR** 作为默认舒适档。

> 单击响应不应跟随“舒适、快速、竞技”变化；这些档位只应控制长按后的连续水平移动和软降节奏。

## 三个概念必须分开

| 概念 | 含义 | 方块空间的设计原则 |
|---|---|---|
| 点击响应 | 手指按下到游戏接收一次左移、右移、软降、旋转或直降指令的时间 | 必须在按下事件立即执行，不额外等待；设备本身已有触控与渲染延迟。 |
| DAS | 按住左移、右移或软降后，自动重复开始前的等待时间 | 用于区分短按“一格移动”和长按“连续移动”；数值越低越敏感，也越容易过冲。 |
| ARR | 自动重复启动后，每次重复移动之间的间隔 | 间隔越小，连续移动越快；过低会在触屏上放大手指微抖和误触的影响。 |

Tetris Effect 的官方社区指南把 DAS 定义为重复输入启动前的时间，把 ARR 定义为持续按住方向输入时的重复频率，并给出其默认值 DAS 166ms、ARR 30Hz（约 33ms/次）。[1] TetrisWiki 同样强调 DAS 和自动重复率分别描述“自动横移开始延迟”和“自动重复节奏”，且不同实现的帧计数口径可能不同，因此应用设置应统一使用毫秒呈现。[2]

## 推荐档位

| 档位 | DAS | ARR | 适用玩家与理由 |
|---|---:|---:|---|
| 舒适（默认） | 160ms | 50ms（20Hz） | 适合大多数触屏玩家；与 Tetris Effect 的 166ms DAS 接近，同时比 30Hz 更容易停在目标列，降低误移。 |
| 快速 | 130ms | 40ms（25Hz） | 适合已熟悉连按节奏、希望更快横移的玩家；仍保留可控的触屏容错。 |
| 竞技 | 120ms | 33ms（约30Hz） | 接近 Tetris Effect 的 30Hz 重复率，适合追求速度且能稳定控制长按时间的玩家。 |

该分档与当前应用的 `160/50ms`、`130/40ms`、`120/33ms` 一致，因此目前的长按参数具有合理的竞技参照与触屏容错梯度；它们不需要因为“快速点击”而再整体下调。

## 为什么不能把数值无限调快

移动端的真实端到端点击延迟受到触控采样、操作系统分发、游戏逻辑、渲染队列和屏幕刷新率共同影响。2024 年一项面向游戏场景的触屏研究在检索摘要中报告，移动设备平均点击延迟为 94–162ms、滑动延迟为 116–187ms；这意味着应用层把 DAS 从 120ms 再降到极低值，并不能等量缩短用户感受到的响应时间，反而更容易造成连续移动过冲。[3]

因此，更科学的策略是优先确保 **首次按下立即执行**，再通过 DAS 控制“要不要进入连续移动”，最后用 ARR 控制“连续移动有多快”。用户若只是觉得点按不灵敏，应先检查是否存在额外的按下等待、动画阻塞或帧率下降，而不是直接把 ARR 降到极低。

## 产品实施建议

《方块空间》应将界面说明固定为“**长按灵敏度**”，而不是“快速点击”。当前三档保留即可。若未来增加高级自定义，建议将可调范围限制为 DAS `100–220ms`、ARR `25–80ms`，并显示“更快 / 更稳”的文字提示；不建议向普通玩家暴露 0ms ARR，因为这会让触屏上的瞬时横移过于难以停止。

最终是否最适合目标用户，应通过设备实测而非纯理论确认。建议记录三类指标：玩家短按时的移动过冲率、长按横移后多走一格的比例，以及 20 分钟连续游戏后的主观疲劳评分。以这三项同时改善为准，可逐步微调默认 DAS 与 ARR。
